# Deye SUN-80K → Elfin EE11A → Zabbix

**Українська** | [English](README.en.md)

Моніторинг інвертора **Deye SUN-80K-SG02HP3-EU-EM6** у Zabbix через Ethernet-шлюз **Elfin EE11A**.

Python-скрипт читає регістри інвертора через Modbus TCP і передає метрики до Zabbix за допомогою `zabbix_sender`. Використовується лише функція **FC03 — читання holding-регістрів**. Скрипт не змінює налаштування інвертора.

```text
Python-скрипт ── Modbus TCP ── Elfin EE11A ── RS485 / Modbus RTU ── Deye SUN-80K
      │
      └── zabbix_sender ── Zabbix server / proxy
```

## Файли

| Файл | Призначення |
| --- | --- |
| [deye_sun80k_elfin_zabbix_v4_1.py](deye_sun80k_elfin_zabbix_v4_1.py) | Опитування інвертора, декодування Warning/Fault та надсилання метрик |
| [template_deye_sun80k_zabbix_7_4_fix.yaml](template_deye_sun80k_zabbix_7_4_fix.yaml) | Шаблон Zabbix **7.4**, 71 елемент даних типу Zabbix trapper |

Підтримуються дані мережі, навантаження, АКБ, інвертора, генераторного порту, температури, добової генерації та чотирьох перевірених PV-каналів. Повідомлення про попередження й аварії містять оригінальні назви та український переклад. Адреси телеметрії PV5/PV6 у цьому скрипті не визначені.

## Вимоги

- Linux із Python 3 та `zabbix_sender`.
- Zabbix 7.4 для імпорту наданого шаблону; сумісність з іншими версіями не перевірена.
- Доступ із машини зі скриптом до Elfin та Zabbix server/proxy.
- Elfin EE11A з увімкненим перетворенням **Modbus TCP ↔ Modbus RTU**. Параметри RS485 мають відповідати налаштуванням інвертора.

Сторонні Python-бібліотеки для запуску скрипта не потрібні. Значення регістрів і масштабування залежать від моделі та прошивки; на іншому обладнанні їх потрібно звірити з показниками інвертора.

## Завантаження та встановлення

Натисніть **Code → Download ZIP** на GitHub або виконайте:

```bash
git clone https://github.com/Rulyan4ik/Deye-sun-80K-zabbix.git
cd Deye-sun-80K-zabbix
```

Приклад для Debian/Ubuntu:

```bash
sudo apt-get update
sudo apt-get install python3 zabbix-sender
command -v zabbix_sender
```

Якщо пакунок недоступний у вашому дистрибутиві, встановіть його з офіційного репозиторію Zabbix для вашої ОС.

## Налаштування

Відредагуйте блок `CONFIG` на початку Python-файлу:

```python
ELFIN_IP = "192.168.31.100"  # ваша адреса Elfin
ELFIN_PORT = 8899           # TCP-порт, налаштований у вашому Elfin
MODBUS_SLAVE_ID = 0         # Modbus-адреса вашого інвертора

SOCKET_TIMEOUT = 3.0
POLL_SEC = 30

ZABBIX_SERVER = "127.0.0.1"  # адреса вашого Zabbix server/proxy
ZABBIX_HOST = "Deye_80k"     # точне поле Host name у Zabbix
ZABBIX_SENDER = "/usr/bin/zabbix_sender"
```

Це початкові значення з наданого робочого скрипта. Вони не визначають параметри вашої мережі автоматично. Параметри скрипта задаються в коді, а не через змінні середовища. Якщо `command -v zabbix_sender` показав інший шлях, змініть `ZABBIX_SENDER`.

### Zabbix

1. Відкрийте **Data collection → Templates → Import** та імпортуйте YAML-файл.
2. Створіть або виберіть хост. Його поле **Host name** має точно збігатися з `ZABBIX_HOST` (початково `Deye_80k`).
3. Прив'яжіть шаблон **Deye SUN-80K SG02HP3** до хоста.
4. Забезпечте доступ від машини зі скриптом до Zabbix server/proxy на TCP-порт **10051**. Якщо для trapper-елементів задані Allowed hosts, дозвольте адресу відправника.

Шаблон отримує дані через trapper-елементи: Zabbix agent для цього скрипта не потрібен. Скрипт використовує стандартний порт Zabbix sender; окремого параметра для іншого порту чи TLS у ньому немає.

## Перевірка та запуск

Спершу перевірте TCP-з'єднання й читання регістра 500, без надсилання до Zabbix:

```bash
python3 deye_sun80k_elfin_zabbix_v4_1.py --test
```

Разове опитування з надсиланням метрик:

```bash
python3 deye_sun80k_elfin_zabbix_v4_1.py
```

Безперервне опитування з інтервалом `POLL_SEC`:

```bash
python3 deye_sun80k_elfin_zabbix_v4_1.py --loop
```

Для завершення натисніть `Ctrl+C`. Перевіряйте фактичні значення в **Monitoring → Latest data** та підсумок `zabbix_sender`: `processed`, `failed`, `total`. Самого нульового коду завершення скрипта недостатньо: він може вивести помилку опитування й завершитися з кодом 0.

Додаткові режими діагностики лише читають регістри та не надсилають метрики:

```bash
python3 deye_sun80k_elfin_zabbix_v4_1.py --probe       # 500..800
python3 deye_sun80k_elfin_zabbix_v4_1.py --probe-full  # 0..2000
```

Повний скан може тривати довго, якщо пристрій відхиляє адреси або не відповідає.

## Відомі особливості

- Скрипт формує **80 метрик**, а шаблон містить **71 ключ**. Дев'ять сирих діагностичних метрик не мають елементів у шаблоні: `deye.warning1.raw`, `deye.warning2.raw`, `deye.fault1.raw`–`deye.fault4.raw`, `deye.load.raw_reg647`–`deye.load.raw_reg649`. Zabbix може відхиляти їх і повідомляти про часткове прийняття пакета. Щоб приймати їх, додайте відповідні числові trapper-елементи до власного шаблону.
- `deye.comm.ok` встановлюється в 1 до читання регістрів. Цей показник сам по собі не гарантує успішного читання всіх даних; перевіряйте значення телеметрії й повідомлення про помилки.
- Відсутні значення (`None`) не надсилаються до Zabbix. Помилка читання аварійних регістрів відображається текстом «Помилка читання Modbus».

## Перевірки цієї публікації

Під час підготовки перевірено читання FC03 на локальному симуляторі, обробку фрагментованих відповідей, приклади масштабування та декодування аварій. Усі 71 ключ шаблону присутні у виході скрипта; YAML розбирається, UUID мають коректний формат. Реальний `zabbix_sender` 7.0.22 передав 80 метрик локальному протокольному симулятору, включно з українським текстом.

Ці перевірки не є перевіркою імпорту в реальний Zabbix чи нового підключення до інвертора. Власник повідомив, що рішення вже працює у його встановленні. Надані Python- і YAML-файли опубліковані без зміни їхнього вмісту.
